# podkop-engine

Неофициальная сборка [sing-box](https://github.com/SagerNet/sing-box) для
[podkop](https://github.com/itdoginfo/podkop) на OpenWrt. **Проект не связан с sing-box и его
авторами**; пакет называется иначе, потому что лицензия sing-box запрещает производным работам
использовать его имя. Бинарь по-прежнему устанавливается как `/usr/bin/sing-box`, пакет объявляет
`PROVIDES: sing-box`, поэтому зависимость podkop от `sing-box` выполняется.

Распространяется на условиях GPL-3.0-or-later (см. `LICENSE`; исходная лицензия sing-box —
`LICENSE.sing-box`). Упаковка основана на `net/sing-box` из openwrt/packages.

## Чем отличается от sing-box из репозитория OpenWrt

| | |
|---|---|
| REALITY | работает с Xray-core 26.7+ и 26.9+ (как Xray-клиент 26.9.9): ClientHello несёт X25519MLKEM768, клиент заявляет версию 26.3.27 |
| отпечатки uTLS | `firefox` = Firefox 148, `safari` = Safari 26.3 (как в Xray), `random` выбирает только из chrome/firefox/safari; `randomized` согласован: X25519MLKEM768 всегда есть и в группах, и в ключах, ALPN всегда (иначе при части запусков — `CurvePreferences includes unsupported curve`, отказ REALITY у Xray 26.9.8+, gRPC без h2) |
| состав (1.13, 1.14) | два пакета, ставится один. `podkop-engine` — только то, что использует podkop: входы tproxy, direct, mixed; выходы direct, socks, shadowsocks, trojan, vless, hysteria2, tuic, selector, urltest (1.14 на x86_64 — 24,3 МБ вместо 29,2). `podkop-engine-full` — плюс все остальные выходы для «Outbound Config», в том числе NaiveProxy; см. ниже. Теги: `with_quic` (Hysteria2, TUIC), `with_utls` (REALITY, `fp=`), `with_clash_api` (дашборд LuCI, YACD) |
| 1.14: без `sing-box api` | нет CLI `sing-box api` и API-сервиса (~6 МБ) |
| DoH (1.13, 1.14) | таймаут одного медленного запроса больше не рвёт соединение вместе с запросами, на которые уже пришли ответы: на стенде 800 из 800 обычных запросов, одно соединение на весь прогон (раньше на пути podkop 1218 из 1600 ответов уходили на резервный DNS) |
| память (1.13, 1.14) | лимит памяти Go следует за памятью, которую система ещё может дать: под нагрузкой сборщик мусора работает раньше OOM-killer (контейнер 128 МиБ, 72 МиБ заняты другим процессом: без лимита OOM-kill в каждом прогоне, с лимитом — ни одного). Простаивающее соединение больше не держит буфер 32 КиБ: VLESS без flow, Trojan, Hysteria2, TUIC, gRPC, Vision с TLS 1.3 внутри — 5–30 КиБ на соединение вместо 37–63; см. ниже |
| журнал DNS (1.13, 1.14) | ошибка обмена с DNS-сервером пишется один раз на сервер, дальше — одна сводка раз в 10 с (раньше 200–400 строк в минуту) |
| urltest: сервер молчит (1.13, 1.14) | соединение, на которое нет ответа дольше обычного для этого сервера (RTO по RFC 6298 + 1 с), запускает внеочередную проверку: молчащий Hysteria2 или VLESS с мёртвым выходом — переключение через ~17 с вместо ~41 с и до 3 минут; таймауты QUIC тоже считаются отказом |
| Vision (1.13, 1.14) | после перехода Vision в прямой режим (TLS 1.3 внутри) данные копируются через splice, без буфера в простое; для этого sing-vmess берётся из форка [FiyeroT/sing-vmess](https://github.com/FiyeroT/sing-vmess) |
| uTLS (1.13, 1.14) | состояние рукопожатия uTLS/REALITY освобождается после рукопожатия (−13 КиБ на соединение) |
| старт без списков (1.13, 1.14) | если remote rule-set не скачался при старте (WAN ещё не поднялся, неверное время, первый узел urltest мёртв), sing-box стартует с пустым списком и докачивает его (5, 10, 20 с, дальше раз в 30 с), а не падает; после докачки один раз запускает `podkop list_update` |
| urltest (1.13) | перепроверяет узлы при смене сетевого интерфейса (как 1.14), а не через 3 минуты |
| urltest: резервные выходы (1.13, 1.14, с r10) | список `fallbacks` в группе: выходы, на которые группа уходит, только когда ни один из `outbounds` не отвечает, — первый живой по порядку списка; как только отвечает основной, группа возвращается на него. Без поля всё как раньше; см. ниже |
| urltest: ссылка проверки загрузки (1.13, 1.14, с r10) | `download_url` в группе: своя ссылка для проверки 64 КиБ, `""` — проверка в группе выключена, поля нет — ссылка из `/etc/config/sing-box`, как раньше; см. ниже |
| транспорт xhttp (1.13, 1.14, с r11) | клиент транспорта XHTTP из Xray-core для VLESS и Trojan: режимы packet-up, stream-up, stream-one и auto, HTTP/1.1, HTTP/2 и HTTP/3, TLS и REALITY, отдельный сервер для скачивания, XMUX. Имена опций — как в sing-box-extended. На стенде против Xray 26.9.9 ведёт себя не хуже его собственного клиента; см. ниже |
| ссылка в outbound (1.13, 1.14, с r11) | `sing-box tools decode-link 'vless://…'` печатает outbound для ссылки, включая параметр `extra` транспорта xhttp; с r13 — для всех протоколов сборки, см. ниже |
| список возможностей (с r11) | `sing-box version` заканчивается строкой `Features:` — по ней podkop решает, какие опции писать в конфиг и показывать в LuCI; см. ниже |
| сниффер (1.13, 1.14, с r10) | один специально собранный QUIC-пакет из LAN больше не роняет sing-box (разбор ClientHello читал за концом расширения); паника любого сниффера стоит одного соединения, а не процесса, и пишется в лог со стеком. UDP-сниф читает не больше 16 пакетов: поток QUIC Initial, который никогда не складывается в ClientHello, держал до 66 пакетов по 16 КиБ на сессию |
| исправления upstream (1.13, 1.14, с r10) | из ветки stable sing-box после 1.14.2: клиенты WebSocket и HTTPUpgrade теряли байты, пришедшие вместе с ответом 101, клиент WebSocket после первого соединения терял заголовок `Sec-WebSocket-Protocol`; повторный UDP-сниф отдавал уже прочитанные пакеты второй раз; переключение urltest закрывало соединения под общей блокировкой группы. Проверки входных данных sing-vmess (Vision, XUDP, mux) — в форке |
| Clash API (1.13, 1.14, с r10) | строки лога для `/logs` формируются, только пока его кто-то читает: с включённым дашбордом строка ниже уровня лога стоит ~45 нс и 1 выделение памяти вместо ~1200 нс и 16 (1.13; 1.14 — ~500 нс и 6). Занятый адрес `external_controller` больше не роняет старт: ошибка в лог, повтор в фоне. Проверка задержек группы с вложенной urltest (дашборд podkop, таймаут 10 с) не ждёт проверок загрузки внутри неё (1.14) |
| списки (1.13, 1.14, с r10) | недоступный remote rule-set пишет ошибку один раз и потом раз в 10 минут со счётчиком (раньше — каждые 30 с, 2880 строк в сутки), и сборка мусора запускается только после реальной загрузки списка |
| init-скрипт (с r10) | лимит дескрипторов 65536 (4096 по умолчанию кончались примерно на 2000 соединений, дальше падали и DNS-запросы), procd ждёт остановки 15 с вместо 5 (sing-box закрывает соединения до 10 с), в системном логе нет escape-кодов цветов |
| xhttp: сброс сети (1.13, 1.14, с r12) | в r11 выход с транспортом xhttp переставал работать до перезапуска sing-box после смены интерфейса по умолчанию (переподключение WAN), первого появления WAN после загрузки или кнопки «закрыть все соединения» в панели; теперь сброс закрывает соединения, и следующее открывается заново |
| резервный DNS (1.13, 1.14, с r12) | отказ сервера считается один раз на событие и только для имён, которые DNS провайдера разрешил: одно «битое» имя или один сброс соединения DoH больше не уводят всю сеть на DNS провайдера; после сброса сети состояние серверов забывается; `ubus` после промаха перечитывается не чаще раза в 30 с |
| FakeIP (1.13, 1.14, с r12) | пока файл кэша не записывается (кончилось место, раздел только для чтения), новые имена получают адреса из памяти, а не остаются без ответа; соединение на устаревший адрес FakeIP пишется предупреждением с причиной |
| REALITY и отпечатки (1.13, 1.14, с r12) | `android` и `360` с REALITY — ошибка конфигурации (эти отпечатки не умеют TLS 1.3); для `edge`, `ios`, `qq` — предупреждение при старте, а ошибка проверки называет отпечаток как вероятную причину (серверы на Xray-core 26.9.8+ их не принимают) |
| проверки при старте (1.13, 1.14, с r12) | неверный `uplink_http_method` и `download` без `server_port` у xhttp отклоняются `sing-box check`; негодная ссылка проверки загрузки urltest из окружения — одно предупреждение при старте; в логе виден код завершения хука восстановления списков |
| HTTP/2 (1.13, с r12) | `golang.org/x/net` поднят до версии линии 1.14: в прежней один кадр HTTP/2 неизвестного клиенту типа (ALTSVC, ORIGIN) от сервера DoH или прокси ронял весь процесс |
| failsafe и init-скрипт (с r12) | служба failsafe работает при любом порядке установки и после обновления с r1–r3, выключается опцией `failsafe`; подряд считаются падения sing-box с промежутком меньше 10 минут (было — меньше часа) |
| ссылки всех протоколов (1.13, 1.14, с r13) | `sing-box tools decode-link` читает ссылки `vless`, `trojan`, `ss`, `socks`, `hysteria2`/`hy2`, `tuic`, а в `podkop-engine-full` ещё `vmess`, `http`/`https`, `hysteria`, `anytls`, `naive+https`/`naive+quic`. Перед печатью outbound строится тем же кодом, что `sing-box check`: напечатанное этот sing-box примет. Опции sing-box, у которых нет общепринятого параметра ссылки, задаются как `sb.<путь опции>`; см. ниже |
| `tls.spoof` (1.13, 1.14, с r13) | опция TLS `spoof` из sing-box 1.14 перенесена в 1.13 и на обеих линиях работает с REALITY: перед настоящим ClientHello уходит поддельный с именем по выбору, который сервер отбрасывает. Поддельный пакет уходит тем же маршрутом, что соединение; см. ниже |
| автосмена отпечатка uTLS (1.13, 1.14, с r13) | если на ClientHello с отпечатком из конфига сервер не отвечает (пакет не подтверждён после двух повторов), соединение сразу пробуется со следующим отпечатком из списка, и рабочий запоминается; включено опцией `utls_fallback` в `/etc/config/sing-box`; см. ниже |
| самопроверка (с r13) | failsafe раз в 20 с спрашивает у sing-box имя через 127.0.0.42; если процесс работает, но не отвечает 49–72 с, он завершается и procd запускает его заново. На стенде DNS возвращался через 56–75 с после `kill -STOP` (52 замера); см. «Failsafe» |
| списки (1.13, 1.14, с r13) | локальный rule-set, который podkop переписывает при обновлении списков, больше не читается одновременно с заменой: на стенде с детектором гонок Go (файл заменяется каждые 150 мс под нагрузкой) r12 даёт десятки сообщений о гонке за минуту, r13 — ни одного. Remote rule-set отклоняется до чтения, если ответ больше предела или начинается не как `.srs`, а ошибка называет размер, `Content-Type` и первые байты ответа: файл 60 МБ под видом списка стоил r12 137–139 МБ памяти, r13 — столько же, сколько без загрузки (21–25 МБ). Загрузка списка через группу urltest не обрывается, когда группа переключается (в r12 — ошибка `use of closed network connection` и повтор) |
| urltest (1.13, 1.14, с r13) | при пропадании маршрута по умолчанию результаты проверок участников не сбрасываются: отказ соединения с ошибкой самого роутера (`network is unreachable`) оценивается через 3 с и только если сеть за это время не объявлена пропавшей. На стенде (podkop с группой из двух серверов, `ifdown wan` на 30 с) r12 терял результаты обоих участников и переключал группу, r13 — нет; после возврата сети проверка проходит через секунду. Принудительная проверка, пришедшая во время идущей, выполняется сразу после неё; отказ соединения даёт одну строку ошибки с тегом выхода вместо двух |
| память на соединение (1.13, 1.14, с r13) | отпечатки `chrome`, `edge`, `ios`, `qq`, `360`, `android` после рукопожатия освобождают расширения ClientHello. На стенде с 5000 соединений и отпечатком `chrome` живая куча на соединение — 23,8 КБ вместо 26,7 через REALITY и 14,0 вместо 16,8 через TLS (−2,9 КБ, обе линии); для остальных отпечатков в тесте −0,4…1,0 КБ. Запись Clash API о соединении не держит состояние сниффера |
| VLESS с `flow` (1.13, 1.14, с r13) | `flow` поверх ws, grpc, http и httpupgrade — предупреждение при старте (каждое соединение такого выхода падает, раньше причина не называлась); `decode-link` такие ссылки отклоняет |
| DNS по UDP (1.13, 1.14) | каждый запрос уходит со своего сокета со случайным портом, как у dnsmasq: публичные резолверы, режущие поток с одного сокета (Яндекс — около 20 запросов в секунду), больше не теряют ответы под нагрузкой. Так же для `detour` в `direct` (резолвер VPN-секции podkop); через прокси — одна общая сессия, как раньше: новая UDP-сессия VLESS/Trojan/SOCKS — это новое TCP+TLS-соединение к серверу |
| DNS по TLS | 1.13: соединения пула, простоявшие больше 8 с, закрываются раньше, чем их молча закроет сервер (Cloudflare и Quad9 — через 10 с): после паузы запросы не падают с EOF. 1.14 (там все запросы идут по одному соединению): не больше 16 запросов в полёте на соединение, остальные — отдельными соединениями, иначе Яндекс сбрасывает соединение |
| резервный DNS (1.13, 1.14) | если DNS-сервер, к которому sing-box ходит напрямую через WAN, не отвечает или отвечает SERVFAIL, ответ берётся у DNS провайдера; см. ниже |
| память DNS (1.14) | запросы, которые dnsmasq присылает на 127.0.0.42, снова обслуживаются без отдельных горутин на каждый запрос (как в 1.13): при 200 запросах в секунду 22 горутины вместо 3000 и 50 МБ памяти вместо 90; сам обмен идёт вне цикла чтения входа, так что медленный запрос не задерживает остальные |
| FakeIP (1.13, 1.14) | таблица «адрес — имя» целиком в памяти, cache.db — её копия, которая дописывается в фоне: ни DNS-запрос, ни новое соединение не ждут файла. Адрес, которым не пользовались сутки, освобождается; новое имя не отнимает адрес у имени, которым пользуются. После падения, OOM или SIGKILL выданные адреса не достаются другим доменам. Если записи для адреса нет, соединение идёт по имени, которое называет сам клиент (TLS, HTTP, QUIC); см. ниже |
| пачки DNS-ответов (1.13, 1.14) | очередь исходящих пакетов UDP-входа — 1024 пакета вместо 64. Раньше, когда готово сразу 70 и больше ответов (dnsmasq держит в работе до 150 запросов), часть ответов выбрасывалась, и клиент ждал их по таймауту — секунды: в тесте пачки по 100 запросов теряли 0,2 % ответов, по 200 — 0,7–0,9 % |
| failsafe | если sing-box падает раз за разом и procd перестаёт его перезапускать, podkop останавливается: dnsmasq возвращается к обычным серверам, интернет и DNS работают без прокси, причина — в логе; при каждом падении в лог пишется и память роутера; см. ниже |
| зависимости | без `kmod-tun` и `kmod-inet-diag` |
| версия | `sing-box version` → `1.14.2-pdk-r2` (версия upstream и ревизия пакета; в r1 было просто `-pdk`) |

Чего нет по сравнению с полным sing-box (ни в одном пакете): серверных входов (кроме tproxy,
direct и mixed, которые слушает podkop), TUN, WireGuard/Tailscale внутри sing-box
(WireGuard/AmneziaWG в podkop подключаются интерфейсом OpenWrt — это работает), DNS-серверов
DoQ/DoH3 и DHCP, служб, ACME и т.п. В `podkop-engine`, кроме того, нет выходов http, vmess, snell,
tor, ssh, shadowtls, anytls, hysteria и naive — они в `podkop-engine-full`. Конфиг с отсутствующим
типом не проходит `sing-box check` с понятной ошибкой: `vmess outbound is not included in this build
(podkop_slim), install podkop-engine-full or rebuild with -tags podkop_full`.

**Совместимость с серверами.** Патченный клиент ведёт себя как Xray-клиент 26.9.9. Единственный
случай, где обычный sing-box работает, а этот — нет: Xray-сервер ≤ 25.4.30 и сайт-прикрытие,
выбирающий X25519MLKEM768 (большинство крупных зарубежных сайтов). Лечится обновлением Xray на сервере.

## Ветки и форматы

Собираются последние теги веток 1.12, 1.13, 1.14 (`versions.env`) под все архитектуры, для
которых sing-box есть в официальном репозитории OpenWrt:

- `.ipk` (opkg, OpenWrt 24.10 и старше) — SDK 24.10;
- `.apk` (apk, OpenWrt 25.12 и snapshot) — SDK 25.12.

Релизы — по одному на ветку (тег `v<версия sing-box>-r<ревизия>`, например `v1.14.2-r1`), файлы
названы как у sing-box: `podkop-engine_1.14.2-r1_openwrt_<pkgarch>.ipk` / `.apk`, плюс `SHA256SUMS`.
С r9 (1.13, 1.14) рядом лежит `podkop-engine-full_<версия>-r<ревизия>_openwrt_<pkgarch>.ipk` / `.apk`.

Go во всех сборках один — закреплённый `lang/golang` из openwrt/packages (Go 1.26.x).

## podkop-engine и podkop-engine-full (1.13, 1.14)

`podkop-engine` содержит то, что пишет в конфиг podkop, и TUIC. Если в «Outbound Config» нужен
другой протокол, ставится `podkop-engine-full`: в нём есть все выходы sing-box, кроме block
(в podkop вместо него действие reject) и bridge, а входы, DNS-серверы и службы — те же, что в
`podkop-engine`.

| | `podkop-engine` | `podkop-engine-full` |
|---|---|---|
| выходы | direct, socks, shadowsocks, trojan, vless, hysteria2, tuic, selector, urltest | то же + http, vmess, snell (1.14), tor (нужен пакет tor), ssh, shadowtls, anytls, hysteria, naive |
| 1.14, x86_64 / mipsel | 24,3 / 25,8 МБ | 26,0 / 27,7 МБ, с NaiveProxy на x86_64 — 37,0 МБ |
| 1.13, x86_64 / mipsel | 21,2 / 22,7 МБ | 22,4 / 23,9 МБ, с NaiveProxy на x86_64 — 33,3 МБ |

(До r9 оба набора были в одном пакете: 1.14 — 29,2 / 31,0 МБ, 1.13 — 25,3 / 26,8 МБ.)

**NaiveProxy** собирается из cronet (сетевой стек Chromium), который sing-box публикует только
для части архитектур, и добавляет к бинарю около 11 МБ. Он есть в `podkop-engine-full` для
x86_64, i386_pentium4, aarch64 (все четыре pkgarch), armv7 с VFP (arm_cortex-a5_vfpv4,
a7_neon-vfpv4, a7_vfpv4, a8_vfpv3, a9_neon, a9_vfpv3-d16, a15_neon-vfpv4), mipsel_24kc,
mipsel_74kc, riscv64_generic и loongarch64_generic. На остальных (mips big-endian — ath79 и
подобные, mips64, armv5/v6, arm без FPU, mipsel_24kf, mipsel_mips32) выход naive отвечает
`naive outbound is not included in this build`. mipsel_mips32 исключён сознательно: cronet собран
под MIPS32r2.

Переход с одного пакета на другой (настройки `/etc/config/sing-box` сохраняются):

```sh
# opkg (OpenWrt 24.10 и старше): podkop зависит от sing-box, отсюда --force-depends
opkg remove --force-depends podkop-engine && opkg install /tmp/podkop-engine-full_<версия>_openwrt_<pkgarch>.ipk
# apk (OpenWrt 25.12 и snapshot): одной транзакцией
```

Обратно — то же с именами наоборот.

## Старт, когда списки не скачиваются

Обычный sing-box при недоступном remote rule-set завершается с `FATAL ... initial rule-set`;
procd после нескольких перезапусков сдаётся, и роутер остаётся без прокси и без DNS
(dnsmasq podkop уже переключил на sing-box). podkop-engine 1.13/1.14 в этом случае стартует с
пустым списком и докачивает его сам. Когда докачка удалась (путь до списков заработал), sing-box
один раз выполняет команду из `SING_BOX_RULESET_RECOVERED_HOOK`; init-скрипт пакета задаёт её,
только если установлен podkop: `/usr/libexec/podkop-engine/lists-recovered` дожидается
стартового `list_update` podkop (если тот ещё идёт) и запускает `podkop list_update` — так
догружаются списки, которые podkop качает сам (подсети в nft, текстовые списки). podkop при этом
не меняется; sing-box не перезапускается. После перезапуска sing-box списки берутся из cache.db,
хук не срабатывает.

## Проверка загрузки перед переключением urltest (1.13, 1.14)

Обычная проба urltest — HEAD на `generate_204`, несколько сотен байт. Сервер за DPI, который
«замораживает» соединение после ~16 КБ (не отвечает, не рвёт), такую пробу проходит с хорошей
задержкой, и группа выбирает его: работают только мелкие запросы. Поэтому перед тем, как
переключиться на член группы, sing-box скачивает через него 64 КиБ. Член, через который
загрузка встала, пропускается (его результат пробы сохраняется, в LuCI он «живой») и пробуется
снова, когда придёт его следующий результат периодической пробы — раз в интервал, пока он
остаётся лучшим по задержке. Если других членов нет, замороженный всё же лучше мёртвого.
Выбранный член не проверяется: заморозка уже используемого сервера здесь не видна.

Включено по умолчанию, настраивается в `/etc/config/sing-box`:

```sh
uci set sing-box.main.urltest_download_check=0     # выключить
uci set sing-box.main.urltest_download_url='https://ajax.googleapis.com/ajax/libs/jquery/3.7.1/jquery.min.js'
uci commit sing-box; service podkop restart
```

URL по умолчанию — `https://speed.cloudflare.com/__down?bytes=65536`: отдаёт ровно столько
байт, сколько попросили, без кэша. Подойдёт любой URL с телом ≥ 64 КиБ или с известной длиной
(`Content-Length`): читается не больше 64 КиБ, Range сервер может игнорировать. Цена — 64 КиБ
на каждое переключение; в покое ничего не скачивается. При обновлении со старых версий оба
параметра дописываются в `/etc/config/sing-box` сами (uci-defaults), заданные значения не
меняются.

С r10 ссылку можно задать в самой группе urltest (`config.json`), так её сможет задавать podkop:

```json
{ "type": "urltest", "tag": "auto", "outbounds": ["a", "b"], "download_url": "https://speed.cloudflare.com/__down?bytes=65536" }
```

Поле группы главнее `/etc/config/sing-box`: `"download_url": ""` выключает проверку для этой
группы, ссылка — включает с ней, даже если `urltest_download_check=0`. Группа без поля берёт ссылку
из `/etc/config/sing-box`, как раньше. Ссылка без схемы `http`/`https` или без хоста —
ошибка `sing-box check`.

## Резервные выходы urltest (1.13, 1.14, с r10)

```json
{
  "type": "urltest", "tag": "auto",
  "outbounds": ["vps-1", "vps-2"],
  "fallbacks": ["backup-vps", "direct-out"]
}
```

Пока хоть один из `outbounds` проходит проверку, группа выбирает среди них, как обычно (по
задержке и `tolerance`); резервные не выбираются, даже если они быстрее. Когда не отвечает ни
один основной (нет результата проверки или загрузка встала), группа берёт первый резервный по
порядку списка, у которого есть результат, — задержки резервных не сравниваются. Как только
любой основной снова проходит проверку, группа возвращается на него; с резервного на более ранний
резервный — так же.

Резервные проверяются в каждом раунде вместе с основными (один HEAD на резервный выход раз в
интервал), поэтому их состояние известно заранее и видно в дашборде. Всё, что группа знает о
трафике (отказ соединения, сервер молчит), и проверка загрузки работают для резервных так же, как
для основных. В списке членов группы (Clash API, LuCI) резервные идут после основных. Тег не
может повторяться в `outbounds` и `fallbacks`. Без этого поля группа работает как раньше.

`fallbacks` и `download_url` есть только в podkop-engine с r10: podkop-engine r9 и старше и
обычный sing-box отвергают такой конфиг (`json: unknown field "fallbacks"`). С r11 о них
сообщает строка `Features:` (см. ниже): podkop пишет эти поля и показывает их в LuCI, только
когда видит в ней `urltest.fallbacks` и `urltest.download_url`.

## Транспорт xhttp (1.13, 1.14, с r11)

```json
{
  "type": "vless", "tag": "xh", "server": "example.org", "server_port": 443, "uuid": "…",
  "tls": { "enabled": true, "server_name": "example.org", "utls": { "enabled": true, "fingerprint": "chrome" } },
  "transport": {
    "type": "xhttp",
    "mode": "auto",
    "host": "example.org",
    "path": "/api/",
    "x_padding_bytes": "100-1000",
    "xmux": { "max_concurrency": "16-32", "h_max_request_times": "600-900" }
  }
}
```

Клиент транспорта XHTTP (SplitHTTP) из Xray-core 26.9.9, только исходящий, для VLESS и Trojan.
Имена опций совпадают с sing-box-extended (`x_padding_bytes`, `sc_max_each_post_bytes`,
`session_placement`, `xmux { … }`, `download { server, server_port, tls, detour, … }`); диапазоны
пишутся как `"100-1000"`, `"30"`, числом или `{"from": 100, "to": 1000}`. Неизвестное поле —
ошибка `sing-box check`.

- **Режимы:** `packet-up`, `stream-up`, `stream-one`, `auto`. `auto` — как в Xray: с REALITY
  `stream-one` (`stream-up`, если задан `download`), иначе `packet-up`.
- **Версия HTTP:** как в Xray. REALITY — HTTP/2; без TLS — HTTP/1.1; единственный ALPN
  `http/1.1` или `h3` выбирает эту версию; иначе HTTP/2.
- **`download`:** отдельный сервер для скачивания со своим адресом, TLS или REALITY и опциями.
- **VLESS `flow`** поверх xhttp не поддерживается: такой outbound не проходит `sing-box check`.

Проверено на стенде против сервера Xray 26.9.9, рядом с клиентом Xray: 104 варианта настроек
(из них 84–85 проходят все проверки, остальные упираются в настройки сервера или прокси
одинаково у обоих клиентов), 900 одновременных сессий на HTTP/2 и HTTP/3, 10 000 соединений
подряд без роста памяти, горутин и дескрипторов, UDP.

Где клиент намеренно ведёт себя иначе, чем клиент Xray:

- **Отдача в заголовках и cookie** (`uplink_data_placement`: `header`, `cookie`): если
  `sc_max_each_post_bytes` не задан, запрос несёт не больше 4096 байт (у Xray — 1 МБ, что не
  проходит ни в один сервер: сервер Xray по умолчанию принимает 8192 байта заголовков). Заданное
  значение используется как есть; если сервер его не принимает (ответ 431 или 413), ошибка
  называет опцию, а остальные соединения выхода продолжают работать.
- **Много соединений на HTTP/3:** когда на QUIC-соединении заканчиваются потоки (сервер
  разрешает 100), открывается ещё одно; клиент Xray в этом случае ждёт (стенд: 900 сессий из
  900 против 300 из 900).
- **Данные перед закрытием:** записанное перед закрытием соединения досылается (до 5 с).
- **Получатель не читает:** неотвеченных запросов отдачи у сессии не больше 32 или 4 МиБ,
  дальше запись ждёт, как в TCP. На HTTP/1.1 запрос отдачи ждёт ответа не дольше 60 с плюс время
  на его размер.
- **Простой:** соединение пула без сессий закрывается через 5 минут.
- **Память:** кадр HTTP/2 при записи не больше 16 КиБ (иначе клиент Go держит 512 КиБ на каждую
  потоковую отдачу), паддинг не больше 64 КиБ, длина идентификатора сессии не больше 1024.

Чего нет: серверной стороны, VLESS Encryption, `finalmask`, Browser Dialer; на 1.13 HTTP/3 идёт
без отпечатка Chrome для QUIC (на 1.14 — с ним, кроме `disable_sni`).

На роутере без аппаратного AES шифр важнее транспорта. MT7621, скачивание 50 МБ: xhttp с
отпечатком `chrome` (он первым предлагает AES-GCM) — 1,9 МБ/с; без `utls` (Go выбирает
ChaCha20) — 3,26 МБ/с при 3,75 МБ/с без прокси.

## Ссылка в outbound: `sing-box tools decode-link` (1.13, 1.14; все протоколы — с r13)

```sh
echo 'vless://…@example.org:443?type=xhttp&security=tls&…&extra=%7B…%7D#name' | sing-box tools decode-link --compact
```

Печатает outbound для одной ссылки (из stdin или аргументом; через stdin ссылку не видно в `ps`).

| Код | Значение | stdout | stderr |
|---|---|---|---|
| 0 | outbound напечатан | JSON | строки `warning: …` — что ссылка просит, а outbound не умеет |
| 2 | ссылку использовать нельзя | пусто | одна строка `error: …` |
| 1 | всё остальное (например, неизвестный флаг) | пусто | — |

Сообщения не повторяют ссылку: в ней секреты. Вызывать из скриптов нужно с `--compact`: sing-box
без этой команды на вызов без флагов печатает справку с кодом 0, а с флагом выходит с кодом 1.

**Напечатано — значит, работает в этой сборке.** С r13 команда перед печатью строит outbound тем
же кодом, что `sing-box check`, как единственный выход конфигурации. Поэтому:

- напечатанный outbound проходит `sing-box check` этого же бинарника (проверено на 1533 ссылках
  четырьмя сборками: 1.13 и 1.14, `podkop-engine` и `podkop-engine-full` — расхождений нет);
- ссылка на протокол, которого в пакете нет, отклоняется словами сборки: `vmess outbound is not
  included in this build (podkop_slim), install podkop-engine-full …`;
- опция, которой нет в этой линии sing-box, — тоже ошибка, а не молчаливый пропуск.

| `tuic://uuid:password@host:port?…` | tuic | оба | `congestion_control`, `udp_relay_mode`, `udp_over_stream`, `zero_rtt_handshake`/`reduce_rtt`, `heartbeat_interval`, `sni`, `alpn`, `allow_insecure`, `disable_sni` |
| `vmess://` | vmess | full | JSON в base64 (v2rayN) и вид URL с параметрами как у vless |
| `http://`, `https://` | http | full | только с портом и без пути: адрес страницы или подписки, вставленный вместо прокси, отклоняется |
| `hysteria://host:port?…` | hysteria | full | `auth`, `peer`, `upmbps`, `downmbps`, `obfs=xplus`+`obfsParam`, `mport`, `alpn`, `insecure` |
| `anytls://password@host[:port]?…` | anytls | full | `sni`, `insecure`, `alpn`, `fp` |
| `naive+https://`, `naive+quic://` | naive | full с NaiveProxy | `user:password`, `sni`, `extra-headers`, `insecure-concurrency`, `cert` |

У tor, ssh, shadowtls и snell вида ссылки нет: их никто не выдаёт ссылками, а нужное им (второй
выход, локальные файлы, ключи узла) ссылке задавать нельзя. Они задаются как outbound в JSON.

### Что отклоняется и о чём предупреждается

Ссылка отклоняется, только когда без запрошенного до сервера не дойти или собранный outbound
заведомо не заработает. То, что решает один клиент или что лишь добавляет проверку, —
предупреждение: outbound печатается и соединяется.

| Отклоняется | Почему |
|---|---|
| VLESS Encryption (`encryption=mlkem768x25519plus…`) | меняет сам протокол, в sing-box её нет |
| `flow` поверх ws, grpc, http, httpupgrade, xhttp и без TLS | на стенде с Xray 26.9.9 не работает ни в одном сочетании: поверх ws и grpc sing-box сам обрывает каждое соединение, поверх httpupgrade отказывает сервер |
| транспорт mKCP; шифрование и заголовки пакетов транспорта QUIC | в sing-box их нет |
| `headerType=http` вместе с TLS | без TLS это транспорт `http` sing-box (на стенде работает), с TLS он говорил бы на HTTP/2 |
| имя сервиса gRPC в виде пути, кроме `/имя/Tun` | sing-box строит путь `/имя/Tun` с именем одним сегментом; другой путь до сервера не доходит (стенд) |
| `fm` (finalmask) с маской, кроме `fragment` и `noise` | остальные маски меняют то, что идёт по сети, и сервер их ждёт |
| отпечаток, которого не знает и Xray, вместе с REALITY | REALITY построен на uTLS |
| Shadowsocks поверх транспорта или TLS Xray; TUIC v4 (токен вместо пароля); `protocol=faketcp` у hysteria | в sing-box этого нет |
| `http(s)://` с путём или без порта | это адрес страницы, а не прокси |

| Предупреждение | Что происходит |
|---|---|
| gRPC `mode=multi` | используется gun: сервер отвечает на оба вида потоков (стенд) |
| gRPC `authority`, не равный имени сервера TLS | sing-box шлёт имя сервера TLS; обратный прокси, выбирающий сервер по authority, может его не найти |
| отпечаток, который знает только Xray (`hellochrome_131`, `randomizednoalpn`) | берётся отпечаток того же браузера; неизвестный никому при TLS — без имитации, как в Xray |
| `pcs`/`pinSHA256`, `vcn` | закреплённый сертификат не поддерживается: сервер проверяется по системным корням, сервер с самоподписанным сертификатом будет отвергнут (Xray закрепляет хеш сертификата, sing-box — хеш ключа, одно из другого не получить). В новых версиях Xray `allowInsecure` убран в пользу `pcs`, так что такие ссылки будут встречаться |
| `pqv` | проверка ML-DSA-65 сервера REALITY не выполняется |
| `fragment`, `noise`, `fm` с масками `fragment`/`noise` | это настройки клиента Xray; у sing-box своя фрагментация: `sb.tls.fragment=1` |
| `ech` в виде «имя+резолвер» | конфигурация ECH спрашивается у DNS sing-box, названный резолвер не используется |
| `?ed=` в пути httpupgrade | ранних данных у этого транспорта в sing-box нет, из пути они убираются |
| неизвестный параметр | игнорируется |

### Опции sing-box без общепринятого параметра: `sb.<путь>`

Опцию выхода, для которой у ссылок нет имени, ссылка называет её путём в конфигурации после `sb.`:

```
vless://…?security=tls&sb.tls.fragment=1&sb.tls.spoof=packagist.org
…&sb.multiplex.enabled=1&sb.multiplex.protocol=h2mux
…&sb.transport.headers.User-Agent=curl%2F8
```

Значение читается по типу, который опция имеет в этой сборке: флаг — `1`/`0`/`true`/`false`,
список — через запятую, остальное — как в конфигурации; значение, начинающееся со скобки или
кавычки, читается как JSON. Путь побеждает то, что ссылка говорит иначе (с предупреждением);
группа опций с выключателем, которую задали и не включили (`sb.multiplex.protocol` без
`sb.multiplex.enabled=1`), — тоже предупреждение. Выход после этого строится как любой другой, и
то, что он отвергнет, становится ошибкой команды.

Имена, которые уже используют клиенты, читаются как соответствующие опции: `tfo`,
`tcp-fast-open`, `tcp_fast_open`; `uot`, `udp-over-tcp`; из Throne — `tls_fragment`,
`tls_record_fragment`, `tls_fragment_fallback_delay`, `tls_spoof`, `tls_spoof_method`,
`mux_protocol`, `mux_max_connections`, `mux_min_streams`, `mux_max_streams`, `mux_padding`,
`brutal_up_mbps`, `brutal_down_mbps`. Голые `mux` и `fragment` — нет: у разных клиентов они
значат разное.

Ссылка — чужой текст: она может настраивать, как достичь её собственного сервера, и ничего больше.
Через `sb.` **нельзя** задать: ссылки на другие объекты конфигурации (`detour`, `domain_resolver`,
`netns`), локальный маршрут (`bind_interface`, адреса привязки, `routing_mark`, `network_strategy`),
локальные файлы (любая опция `*_path`), возможности системы (`tls.engine`, kTLS), realm у
hysteria2, устаревшие опции, а также то, что ссылка говорит сама (`type`, `tag`, `server`,
`server_port`). Полный список по каждому типу выхода, с причиной отказа, лежит в исходниках
(`common/sharelink/testdata/options-1.13.txt`, `options-1.14.txt`): тест не даёт появиться новой
опции, пока её не отнесут к одному из двух классов.

## Поддельный ClientHello: `tls.spoof` (1.13, 1.14, с r13)

Опция TLS `spoof` появилась в sing-box 1.14: перед настоящим ClientHello по тому же соединению
уходит поддельный, с именем из опции, собранный так, чтобы сервер его отбросил (`spoof_method`:
`wrong-sequence` по умолчанию, `wrong-checksum`, `wrong-ack`, `wrong-md5`, `wrong-timestamp`).
Фильтр на пути, решающий по первому ClientHello соединения, видит поддельное имя. То же делает
опция правила маршрута `tls_spoof`. В r13:

- опция перенесена в линию 1.13 (только Linux; пакеты совпадают с пакетами 1.14 побайтно);
- на обеих линиях она работает с REALITY: upstream её там запрещает, письменной причины запрета
  нет, проверка подлинности REALITY считается по настоящему ClientHello и поддельный её не
  задевает;
- поддельный пакет уходит тем же маршрутом, что соединение: сырой сокет получает метку,
  интерфейс и локальный адрес соединения (в upstream — нет, и при `routing_mark`,
  `bind_interface` или `auto_detect_interface` пакет мог уйти через другой интерфейс);
- чтение номеров последовательности не шлёт лишний пробный пакет перед ClientHello;
- `wrong-timestamp` отклоняется на соединении без меток времени TCP: сервер принял бы там
  поддельный ClientHello за данные;
- сырой сокет открывается в момент отправки, а не при создании соединения: в upstream он
  оставался открытым навсегда, если рукопожатие обрывалось до первой записи.

В ссылке опция задаётся как `sb.tls.spoof=<имя>` и `sb.tls.spoof_method=<способ>`.

Что нужно знать:

- **Нужны права.** Сырой сокет и чтение состояния TCP требуют root (`CAP_NET_RAW` и
  `CAP_NET_ADMIN`); podkop запускает sing-box от root. Без прав каждое соединение выхода
  падает с ошибкой, называющей нужные права.
- **Маскировка слабее.** По соединению идут два ClientHello с разными именами и разной формы;
  наблюдатель, который смотрит на оба, это видит. Формулировка upstream «неотличим» для
  поддельного пакета неверна: он собран стандартной библиотекой Go, а не копирует настоящий.
- **Способ зависит от сервера и пути.** Сервер должен отбросить поддельный пакет: `wrong-md5`
  отбрасывает Linux, собранный с TCP-MD5 (обычные дистрибутивы), `wrong-checksum` могут
  исправить или отбросить по дороге. По сообщениям с мест, некоторые фильтры рвут соединение,
  заметив подделку; у нас это не воспроизводилось.
- **Имя своё у каждого оператора.** Какое имя пропускает фильтр, sing-box не знает; его задаёт
  пользователь.

Проверено: модульные и интеграционные тесты (root, tcpdump, все пять способов, IPv4 и IPv6) на
обеих линиях; с настоящим сервером REALITY (Xray 26.3.27) через сеть с NAT — 12 из 12 запусков,
все пять способов, обе линии; в контейнерах OpenWrt с настоящим podkop (его правила nft,
`auto_detect_interface`) и бинарниками из пакетов обеих линий поддельный ClientHello выходит на
сторону WAN с того же адреса и порта, что настоящий, при всех пяти способах. Не проверено на
железе роутеров: `TCP_REPAIR` и сырой сокет на их ядрах.

## Автосмена отпечатка uTLS (1.13, 1.14, с r13)

Фильтр, решающий по ClientHello, может отбрасывать ClientHello одного браузера и пропускать
другого. Соединение TCP при этом устанавливается, ClientHello уходит и остаётся без
подтверждения, а рукопожатие ждёт весь свой таймаут — на каждом соединении.

С включённой автосменой sing-box во время рукопожатия с отпечатком uTLS следит за соединением
(`TCP_INFO`, раз в 50 мс). Если записанное не подтверждено после двух повторов подряд (на пути с
задержкой 50 мс это около секунды; жёсткий предел 5 с) и сервер ничего не прислал, соединение
закрывается и устанавливается заново со следующим отпечатком: сначала тот, что в конфиге, потом
список, не больше трёх рукопожатий на одно соединение. Сработавший отпечаток используется
дальше — до перезапуска и отдельно для каждого локального адреса (другой адрес — другая сеть,
там может работать и настроенный). Если запомненный перестал получать ответ, перебор идёт дальше.

```
option utls_fallback '1'
option utls_fallback_order 'safari,randomized,firefox,chrome'
```

в `/etc/config/sing-box` (после изменения — `service sing-box restart`); init-скрипт передаёт
список в `SING_BOX_UTLS_FALLBACK`. `utls_fallback '0'` выключает автосмену; без переменной
поведение как у upstream. Имя, которого sing-box не знает, выключает автосмену с одним
предупреждением.

В журнале:

```
tls: ClientHello to 203.0.113.5:443 unanswered with fingerprint chrome, retrying with safari
tls: fingerprint safari is answered where chrome was not; it is used from now on
tls: ClientHello to 203.0.113.5:443 unanswered with all fingerprints (chrome, safari, randomized, firefox)
```

Ограничения:

- только Linux и только соединение, которое sing-box сам открыл как сокет TCP: не через
  `detour`, не для hysteria2/tuic (у QUIC отпечатка uTLS нет), не для shadowtls;
- на линии 1.13 не действует вместе с ECH и kTLS;
- для REALITY из списка не берутся `edge`, `ios`, `qq`, `android`, `360` (REALITY с ними не
  работает или работает только со старыми серверами);
- с `tls.spoof` рабочий отпечаток не запоминается: безответным может быть сам поддельный пакет,
  и сообщение об исчерпании списка говорит об этом;
- сервер, который принял соединение и молчит по другой причине, тоже вызовет перебор: до трёх
  соединений по секунде вместо одного ожидания таймаута.

Проверено на стенде: сервер Xray за правилом nftables, отбрасывающим ClientHello `chrome`, и
sing-box из пакетов обеих линий. Без списка ни один из трёх запросов не проходит (по 8 с
ожидания). Со списком первый запрос проходит за 0,7 с (одно потерянное ClientHello и повтор с
`safari`), следующие — за 0,01 с; с `safari` в конфиге смены нет. На живом пути 2026-10-08 отброшенного ClientHello получить не
удалось (отвечают и `chrome`, и `edge`), поэтому там проверено только отсутствие ложных
срабатываний: 10 запусков из 10, обе линии, в том числе вместе с `tls.spoof`. Порядок по умолчанию взят из замеров 2026-10-07 на одном провайдере.

## Резервный DNS (1.13, 1.14)

Работает только вместе с podkop и включён по умолчанию. Выключается так:
`uci set sing-box.main.dns_fallback=0; uci commit sing-box; service podkop restart`.
При обновлении со старых версий параметр `dns_fallback` дописывается в `/etc/config/sing-box`
сам (скрипт uci-defaults пакета), уже заданное значение не меняется.

**Какие серверы.** Решение принимается один раз, по конфигу sing-box: сервер резервируется,
если sing-box ходит к нему обычным сокетом (без `detour` или с `detour` на `direct`), без
привязки к интерфейсу, метки маршрутизации, адреса источника или netns, и адрес сервера —
публичный или доменное имя. Не резервируются: серверы за прокси и группами outbound, серверы
VPN-секций podkop («Резолвер доменов» ходит через `bind_interface` туннеля), локальные и
частные резолверы (AdGuardHome на `127.0.0.x` или в LAN, `10.x`, `192.168.x`, `100.64.x`).
Маршруты самой системы не учитываются: сервер, заведённый в VPN маршрутом, а не через секцию
VPN podkop, выглядит как обычный. В логе при первом запросе к серверу:
`server dns-server falls back to provider DNS when it fails` или
`no provider DNS fallback for server <тег>: <причина>`.

**Когда.** Сервер не ответил за 3,5 с, отказал в соединении, сбросил его, ошибка TLS/HTTP — запрос
повторяется у DNS провайдера. После двух таких отказов подряд сервер отставляется: запросы сразу
идут провайдеру, а сервер раз в 30 с (дальше реже, до 5 минут) проверяется копией запроса;
первый нормальный ответ возвращает его. SERVFAIL тоже переспрашивается у провайдера, но сервер не
отставляет (обычно это ошибка одного домена). TTL ответов провайдера — не больше 60 с. Если
провайдер не ответил два раза подряд, резерв для этого сервера выключается на минуту (sing-box
ведёт себя как без него), потом провайдер пробуется снова. NXDOMAIN — это ответ, провайдеру он не переспрашивается.

**DNS провайдера** — DNS-серверы интерфейсов OpenWrt на выходном устройстве sing-box (на него
sing-box привязывает сокеты: `auto_detect_interface` или «Output Network Interface» в podkop),
из netifd через ubus. У DHCP и PPPoE это DNS интерфейсов wan и wan6 (wan_6). Туннели VPN,
LAN с DNS, заданным вручную, и резервный модем — другие устройства, их DNS не берутся
(`resolv.conf.auto`, где OpenWrt сваливает DNS всех интерфейсов, не используется). Список
читается при первом запросе к такому серверу и заново, когда sing-box меняет выходной интерфейс
(переключение uplink, WAN упал и поднялся, новая сессия PPPoE), когда ни один сервер не
ответил, и через 30 с, если ubus не ответил.

Из нескольких серверов берётся самый быстрый, как у dnsmasq: первый запрос уходит всем сразу,
следующие — тому, кто ответил первым; всех снова спрашивают раз в 20 с или 50 запросов и сразу,
если он не ответил. Запрос к провайдеру идёт тем же путём, что и к серверу, со своего сокета;
у этих сокетов свой лимит (256), так что всплеск запросов, ждущих молчащий сервер, не мешает
ответам провайдера.

## FakeIP (1.13, 1.14)

В обычном sing-box таблица FakeIP живёт в cache.db. Каждый поиск читает файл; каждое новое имя —
отдельная запись в файл, которой ждёт DNS-ответ (не больше ~100 новых имён в секунду). Позиция
выдачи попадает в файл только при штатной остановке: после падения адреса раздаются заново с
начала диапазона, и устройство со старым адресом попадает на чужой сайт. Диапазон обходится по
кругу вслепую, записи не удаляются никогда.

Здесь таблица целиком в памяти; cache.db читается один раз при старте и дальше только получает
изменения.

**Скорость.** Имя и адрес ищутся в памяти (60 нс вместо 650). Новое имя получает ответ сразу;
изменения пишет фоновый цикл — всё, что накопилось, одной транзакцией, без пауз. Пачка из 100
новых имён получает последний ответ через 2–5 мс, и с cache.db на флешке тоже (обычный sing-box —
около секунды).

**Запись в файл.** Одна транзакция cache.db — это 20–35 КБ записи, сколько бы имён в ней ни было.
Обычный sing-box делает транзакцию на каждое новое имя. Здесь всё, что пришло, пока пишется
предыдущая транзакция, уходит следующей: когда имена приходят по одному, выходит 21 КБ на имя
вместо 29–35; когда пачкой — 5 КБ на имя с cache.db в `/tmp` и 0,3 КБ на флешке (эмуляция
SPI-NAND; там транзакция пишется дольше, и в неё попадает больше имён).

**Срок жизни адреса.** Адрес занят, пока им пользуются: считаются DNS-запрос имени и новое
соединение на адрес. Сутки без использования — запись удаляется, cache.db не растёт без конца.
Если в диапазоне занято больше четверти адресов (для `198.18.0.0/15` — 32 767), уходят те,
которыми не пользовались дольше всех, но не использованные за последний час; жёсткий предел —
вдвое больше. Новое имя берёт следующий свободный адрес, занятые пропускаются.

**Падения.** Позиция выдачи сохраняется с запасом в 1024 адреса. После остановки без сохранения
(падение, OOM, SIGKILL) выдача продолжается за запасом, а свободные адреса внутри него час не
выдаются: адрес, выданный перед самым падением, другому домену не достанется. Запись уходит из
памяти только после того, как удалена из файла.

**Адрес без записи.** Имя, выданное за мгновение до падения, может не успеть в файл; запись
могла быть удалена как неиспользуемая, а устройство адрес ещё помнит. Соединение на такой адрес
идёт по имени, которое называет сам клиент: TLS SNI, HTTP Host, QUIC (нужно правило `sniff`, в
конфиге podkop оно есть). Если клиент имени не называет, соединение отклоняется
(`missing fakeip record`), как раньше; на чужой сайт оно не попадает. QUIC на стенде не проверялся.

**Цена.** Около 170 байт памяти на имя: 5 МБ на 30 000 имён. Файл cache.db при этом вдвое меньше.

**Совместимость cache.db.** Формат файла прежний, в нём остаётся одна таблица «адрес → имя» и
позиция выдачи. Файл обычного sing-box и прежних ревизий читается как есть, имена сохраняют
адреса. Если вернуться на прежнюю ревизию или обычный sing-box, файл откроется, но известным
именам один раз будут выданы новые адреса (таблицы «имя → адрес» в файле больше нет).

Имена сравниваются без учёта регистра. «Flush FakeIP» в Clash API (кнопка в дашборде) очищает и
память, и файл.

## Память (1.13, 1.14)

Сборщик мусора Go по умолчанию даёт куче вырасти вдвое против живых данных, прежде чем
запуститься. На роутере со 128 МБ под нагрузкой это доводит до OOM-killer, и вместе с sing-box
падают прокси и DNS. Здесь sing-box держит лимит памяти Go (`GOMEMLIMIT`) равным памяти Go плюс
тому, что система ещё может дать (`MemAvailable`, а в cgroup с лимитом — остаток до него), минус
страницы собственного кода; пересчитывает его после каждой сборки мусора. Собственные выделения
лимит не двигают, его сдвигают только другие процессы, когда берут или отдают память. Когда памяти
мало, сборщик работает чаще и раньше отдаёт свободные страницы системе. Когда памяти много, лимит
не мешает: процессор тратится так же, как без него. При старте в лог пишется
`memory limit <N>, following the available memory`.

Задать лимит вручную или выключить:

```sh
uci set sing-box.main.memory_limit=64MiB      # фиксированный лимит
uci set sing-box.main.memory_limit=off        # без лимита
uci commit sing-box; service podkop restart
```

Значение передаётся как `GOMEMLIMIT` (единицы B, KiB, MiB, GiB, TiB); строку другого вида
init-скрипт пропускает с записью в лог: Go с неверным `GOMEMLIMIT` не стартует.

## Failsafe

Служба `/etc/init.d/podkop-engine` слушает события procd.
Одиночное падение sing-box procd перезапускает сам, в логе отмечается причина (в том числе
OOM-killer). Если sing-box падает раз за разом и procd перестаёт его перезапускать, dnsmasq
продолжает слать все запросы на `127.0.0.42`, где уже никто не слушает, — сеть остаётся без DNS.
В этот момент служба выполняет `/etc/init.d/podkop stop`: podkop возвращает dnsmasq к обычным
серверам и убирает свои правила nft, интернет работает без прокси. В лог пишется причина и
последняя ошибка sing-box. При каждом падении туда же пишется память: MemTotal и MemAvailable,
сколько занимал sing-box, если его убил OOM-killer, заполнение /tmp и размер cache.db, три самых
больших процесса — видно, кончилась ли память роутера (Wi-Fi, другие службы) или вырос sing-box.
Запустить podkop снова — `service podkop start` или перезагрузка,
когда причина устранена. Расход: три процесса `sh` и `ubus subscribe`;
раз в 5 с проверяется, не перезапускался ли ubusd, раз в 20 с — один запрос `dig`.

**Самопроверка (с r13).** procd не перезапускает sing-box, который работает, но не отвечает
(взаимная блокировка, зависание), а dnsmasq продолжает слать ему все запросы — сеть без DNS, как
после серии падений. Поэтому служба раз в 20 с спрашивает у sing-box через `127.0.0.42`
проверочное имя podkop (`fakeip.podkop.fyi`; sing-box отвечает на него сам, адресом FakeIP, без
обращения к серверам). Годится любой ответ. После трёх запросов подряд без ответа (49–72 с
тишины) процесс завершается, procd запускает его заново, и это считается падением: шесть
зависаний подряд останавливают podkop так же, как шесть падений. Чтобы не убить здоровый процесс:

- проверка «взводится» только ответом того же процесса: sing-box, который ещё ни разу не
  ответил (другая конфигурация, идёт запуск), не трогается;
- во время `podkop list_update` запросы не считаются;
- PID берётся у procd, а не по имени: `sing-box check` и `decode-link` — тоже процессы sing-box;
- есть ли podkop, проверяется при каждом опросе: самопроверка начинает работать без
  перезагрузки, в каком бы порядке ни ставились пакеты.

На стенде (OpenWrt 24.10 с 1.13 и 25.12 с 1.14, настоящий podkop): после `kill -STOP` DNS
возвращался через 56–75 с во всех 52 замерах; ни одного лишнего завершения
за 30 минут простоя, 10 перезапусков podkop, 3 `list_update`, 3 минуты без WAN, запуск без WAN и
4 остановки по 45 с с продолжением. Отдельно проверены пакеты на свежем OpenWrt 24.10 с настоящим
procd, оба пакета обеих линий: podkop-engine до podkop, после него и обновление с r12 на месте —
самопроверка срабатывает и до перезагрузки, и после неё. Выключить только самопроверку: `uci set
sing-box.main.liveness=0; uci commit sing-box; service podkop-engine restart`. На железе под
нагрузкой (MT7621) не проверялось; если самопроверка завершает здоровый sing-box, в журнале будет
строка `has not answered DNS on 127.0.0.42 for N s`.

Когда failsafe останавливает podkop, причина и состояние памяти записываются ещё и в
`/etc/sing-box/failsafe.last` (с r13): журнал живёт в памяти и теряется при перезагрузке. Дата в
файле — время события; файл перезаписывается при следующем срабатывании.

procd считает падения подряд, если между ними меньше 10 минут (`respawn 600 5 5`), и сдаётся на
шестом; более редкие падения он перезапускает каждый раз. До r12 порог был час (умолчание procd),
и шесть падений с промежутками в десятки минут останавливали podkop насовсем.

С r12 служба запускается и включается независимо от порядка установки: раньше она не работала до
перезагрузки, если podkop ставили после podkop-engine, и пропадала после перезагрузки у тех, кто
обновлялся на месте с r1–r3. Выключить: `uci set sing-box.main.failsafe=0; uci commit sing-box;
service podkop-engine restart`.
